# Languages: how Folia speaks German and English, and how another language is added

> State: 2026-09-27. German and English. Owner: „Als erstes möchte ich support für deutsch und
> englisch. Aber ich will später noch die option haben andere sprachen hinzu zu fügen" — every
> language is written left to right, top to bottom. And: „du musst die module nicht übersetzen.
> Nur das, was im ui der app steht."

## 1. What is translated

- **What the app writes itself** is translated: the words of the pages (navigation, headings,
  buttons, hints, empty states, errors, `aria-label`s and `title`s, the sentences of the
  Stundenplan and the finder), the labels of the codes of the data (`folia_model::labels`:
  „Vorlesung" / "Lecture", „Pflicht" / "Compulsory"), dates, numbers and semester names, the
  link-preview cards the server draws, and what the calendar feed writes around the data.
- **What the data says is not** (owner, 2026-09-27): module titles and descriptions, the names of
  programs, areas, departments, rooms and people, QIS's own words for an event („Vorlesung/Übung"
  as QIS types it) are shown as the BTU writes them, in every language. A module's texts carry the
  language they are written in (`lang` from `v_module.page_lang`, 2026-10-01): on the English page
  a German text is hyphenated in its Blocksatz, and read out, as German.
- The legal pages are translated; the German text stays the one that counts, and the English
  pages say so.

## 2. Addresses

One language is one address (R9: the server's HTML depends on the address and the snapshot only).

| Address | Language |
|---|---|
| `/`, `/catalog?…`, `/catalog/module/<id>`, … | German, the default: the addresses as they always were |
| `/en`, `/en/catalog?…`, `/en/catalog/module/<id>`, … | English |
| `/de/…` | not an address of the site: `301` to the plain address |
| `/en/cards/…`, `/en/calendar/<code>.ics` | the cards and the calendar feed in English |

- `folia_locale::Locale` is the list of languages: its code, its prefix, `Locale::path` (a path of the
  app as a link of that language writes it) and `Locale::split` (the language of an address and
  the path of the app it names).
- **Inside the app every path is without the prefix.** The router works below it
  (`<Router base=locale.prefix()>`), `app::i18n::use_location` reads the path without it, and
  `navigate`/`Pending::go` take plain paths (the router adds the prefix). Whatever *writes* an
  address into a page writes `t.path(…)`: `href=t.path(url::CATALOG)`,
  `href=move || t.path(&url.path())`, `action=t.path(url::CATALOG)`. A server test renders the
  English pages and fails on any link into German.
- **A link into another language is a new page load** (`rel="alternate external"`,
  `app::languages`): the language of a running app never changes. What a visitor keeps in the
  browser (Merkliste, Stundenplan, „Mein Studiengang", the tabs' memory) belongs to the site,
  not to a language: it stays when the language changes.
- **The switch** (owner, 2026-09-27; `app::languages`): a button per other language, the icon of
  languages over its code („EN"). On the desktop it stands in the rail directly above the switch
  between light and dark, as large as it. A phone has no rail: there it stands at the end of the
  start page's brand line, framed as a 44 px target — one tap away through „Start", and far from
  the bottom bar and the lists, so that no thumb hits it by accident. It is a plain link, so it
  works without JavaScript too.
- **With JavaScript the browser picks the language** (owner, 2026-09-27: „in der js version
  automatisch auf die browser sprache gewechselt … im local storage gespeichert … beim nächsten
  besuch wird immer auf die gespeicherte sprache gewechselt"): the first script of the head
  (`app::languages::language_script`) takes the language kept in `localStorage`
  (`betula.language`), else the first of `navigator.languages` the site speaks (else the default,
  German), keeps it, and replaces a page in another language by the same address in that one
  before anything is drawn. The switch keeps the language it leads to before it leads there
  (`enhance.js`), so a choice is never undone. Nothing happens where nothing can be kept (storage
  blocked: the next page would take a choice back), nor for crawlers and automated browsers
  (`navigator.webdriver`, a bot's user agent): search engines must see every language at its own
  address. The server itself never picks a language (no redirect by `Accept-Language`: the page of
  an address is the same for everybody, R9); search engines learn every language of a page from
  `hreflang` in the page's head and in the sitemap. The privacy notice names the kept language
  („Speicher im Browser").

## 3. Texts

Texts are Rust values, so a language that lacks a text does not compile.

- `folia/crates/locale/src/` — the words of the data contract: `common` (weekdays, months, dates,
  semester names, number separators) and the other groups of the catalog crate. Code labels live
  with their codes (`folia_model::labels`: `Winter = "winter" => { de: "Wintersemester", en: "Winter
  semester" }`); small label functions of other enums take a `Locale` and match on it.
- `folia/crates/<crate>/src/i18n/` — the words of the pages, one group per part of the app, in the
  crate of that part (`folia-design`: `common`, `ui`, `format`, `combobox`; `folia-shell`: `app`,
  `ground`, `seo`; `folia-widgets`: `catalog`, `module`, `week`; a feature its own, as
  `folia-planner` the `studyplan_*` groups). A group is a struct with one field per text and one
  `const` per language:

```rust
pub struct Texts {
    /// The heading of the filter panel.
    pub filters: &'static str,
    /// „17 Module": a text with values in it is a function, so each language builds its own
    /// sentence (plural, word order).
    pub found: fn(u64) -> String,
}

pub const DE: Texts = Texts { filters: "Filter", found: |n| format!("{n} Module") };
pub const EN: Texts = Texts { filters: "Filters", found: |n| if n == 1 { "1 module".into() } else { format!("{n} modules") } };
```

- Each crate puts the groups it writes together with `folia_design::texts!` in its
  `src/i18n/mod.rs` (its own, and those of the crates below it it needs) and gets its `Texts`,
  `DE`, `EN`, `texts(locale)` and `t()`. A component takes the texts once, `let t = i18n::t();` (a `&'static`, `Copy`, free to move into
  closures), and writes `{t.catalog.filters}`, `{(t.catalog.found)(n)}`, `t.locale` where a
  function of the domain needs the language, `t.path(…)` for a link. A function outside a
  component takes the `Locale` or its own crate's `&Texts` as a parameter (never another crate's:
  a function another crate calls takes the `Locale`); `i18n::locale()` reads the
  language from the context where nothing hands it in.
- The server has its own few texts (`folia/crates/server/src/texts.rs`: the cards, the manifest, the login
  page of closed testing); `folia/assets/boot.js` and `enhance.js` carry theirs in a small table of
  the languages, found by the prefix of the address as `Locale::split` finds it.

## 4. Adding a language

1. `folia/crates/locale/src/lib.rs`: a variant of `Locale` (e.g. `Fr`), its code (`"fr"`), prefix
   (`"/fr"`), name in itself (`"Français"`) and territory (`"fr_FR"`), and add it to
   `Locale::ALL`. From here the compiler lists every place that needs the new language.
2. Every text group: a `pub const FR: Texts = Texts { … }` beside `DE` and `EN`
   (`folia/crates/locale/src/*.rs`, `folia/crates/*/src/i18n/*.rs`, `folia/crates/server/src/texts.rs`), and the language in
   the `texts!` macro of `folia/crates/design/src/i18n/mod.rs` (a `static FR` and its arm of
   `texts()`), which every crate's texts are made with.
3. The code labels: `fr: "…"` in every `code_enum!` of `folia/crates/model/src/labels.rs` (and the macro's
   pattern), and a `(Locale::Fr, …)` arm in each label function the compiler names.
4. `folia/assets/boot.js`, `enhance.js`: the language's row in their tables of texts.
5. Nothing else: routes, the sitemap, `hreflang`, the cards, the calendar feed and the switch
   follow `Locale::ALL`.
